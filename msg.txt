Compute link state from real runs, and read run history from Fabric

The link state was written once at creation and never recomputed, so
every link stayed Planned for ever no matter what happened to it. There
was no rule behind Active, Planned and Warning; the words were decoration.

They now mean something:

  Warning  the notebook could not be created, or the most recent run failed
  Active   a run is in progress, or a schedule is enabled, or the last run succeeded
  Planned  the link is saved but nothing runs it yet

Each state carries the sentence that justifies it, so a Warning names
the Fabric failure rather than leaving the reader to guess.

Run history was never read back from Fabric. It held only what the
current browser session had started, which is why a failed scheduled run
left Monitoring empty. It now reads job instances from the API for every
link that has a notebook, including runs started by a schedule or from
the Fabric portal, and surfaces failureReason verbatim.
